1. 프로젝트 개요

1.1 프로젝트 목적

본 프로젝트는 단순한 운동 기록 앱을 넘어, 게임적 요소(Gamification)를 접목한 피트니스 웹 애플리케이션 ’FitGame’을 설계 및 구현하였다. 사용자가 운동을 기록할 때마다 점수와 경험치(EXP)를 획득하고, 레벨·티어 시스템 및 1:1 배틀 기능을 통해 경쟁과 동기부여를 동시에 경험할 수 있도록 하였다.

1.2 개발 배경

현대인의 운동 지속률은 낮으며, 기존 피트니스 앱은 ’기록’에만 집중하여 흥미를 유지하기 어렵다는 문제를 발견하였다. 이에 게임의 보상 심리(레벨업, 업적, 랭킹)와 소셜 경쟁 요소를 결합함으로써 운동 지속 동기를 높이는 서비스를 개발하고자 하였다.

1.3 주요 기능

4. 주요 기능 설명

4.1 운동 기록 및 점수 계산 시스템

사용자가 운동 종류를 선택하고 세트 정보(무게·반복 수) 또는 유산소 정보(시간·거리)를 입력하면, 서버에서 운동 타입별 가중치를 적용하여 점수를 자동 계산하였다. 계산된 점수의 1/10이 EXP로 변환되며, 최소 10 EXP를 보장하도록 구현하였다.

운동 유형 점수 계산 공식 가중치 예시
근력 운동 (무게 × 반복 × 세트 수) / 10 × 가중치 스쿼트 1.3, 데드리프트 1.4
유산소 운동 시간(분) × 가중치 러닝 2.0, 사이클 1.5
자유 운동 시간(분) × 1.0 기본 가중치 적용

4.2 레벨 · 티어 시스템

레벨업에 필요한 누적 EXP는 100 × N × (N+1) / 2 공식으로 계산하여 레벨이 높을수록 더 많은 운동이 필요하도록 설계하였다. 레벨 구간에 따라 5단계 티어(Bronze → Silver → Gold → Platinum → Diamond)가 자동으로 부여된다.

4.3 실시간 배틀 (Socket.io)

친구에게 배틀을 신청하면, 양측의 주간 점수를 비교하여 즉시 승패를 결정하였다. Socket.io를 활용하여 배틀 결과, 레벨업 알림, 업적 달성 알림이 모든 연결된 클라이언트에 실시간으로 전달되도록 구현하였다.

4.4 AI 코치 (OpenAI API)

사용자의 운동 기록을 분석하여 GPT-3.5-turbo 모델에게 맞춤 피드백과 루틴 추천을 요청하였다. OpenAI API 키가 없는 경우에도 데모 모드로 자동 전환되어 서비스가 중단 없이 동작하도록 설계하였다.

5. 주요 코드 리뷰

5.1 SPA 라우터 (app.js — navigateTo 함수)

항목 내용
사용 파일 public/js/app.js
구현 목적 페이지 전체를 새로고침하지 않고, 특정 섹션만 보이도록 전환하는 SPA 라우터 구현
동작 원리 모든 .page 요소에 hidden 클래스를 추가한 뒤, 요청된 page ID에만 active 클래스를 부여함 
async function navigateTo(page, force = false) {
  if (!force && currentPage === page) return;
  currentPage = page;

  document.querySelectorAll('.page').forEach(el => {
    el.classList.add('hidden');
    el.classList.remove('active');
  });

  const section = document.getElementById(`page-${page}`);
  if (section) {
    section.classList.remove('hidden');
    section.classList.add('active');
  }

  if (page === 'dashboard') await window.GamePage?.loadDashboard?.();
  if (page === 'workout')   await window.WorkoutPage?.init?.();
  // ... 각 페이지별 초기화 함수 호출
}

위 코드는 서버 요청 없이 클라이언트 측에서 화면을 전환하는 SPA의 핵심 라우터이다. hidden/active CSS 클래스를 DOM에 동적으로 조작하여 불필요한 서버 재요청을 방지하고 빠른 화면 전환을 실현하였다. 또한 Optional Chaining(?.)을 사용하여 각 모듈이 로드되지 않은 경우에도 오류 없이 동작하도록 방어 코드를 적용하였다.

5.2 운동 점수 계산 로직 (server/routes/workout.js)

항목 내용
사용 파일 server/routes/workout.js, server/config/gameConfig.js
구현 목적 운동 종류에 따라 점수를 계산하고, EXP로 변환하여 사용자 스탯에 누적
동작 원리 운동 타입(strength/cardio)에 따라 다른 공식을 적용, EXP = score / 10 + 최소 10 EXP 보장 
// 점수 계산 (핵심 게임 로직)
const score = calculateWorkoutScore(workoutData);
const expGained = Math.round(score / EXP_PER_SCORE) + 10; // 최소 10 EXP

// 사용자 스탯 업데이트
const { leveledUp, newLevel } = user.addExp(expGained);
user.gameStats.totalScore += score;
user.gameStats.weeklyScore += score;

// 레벨업 시 Socket.io로 즉시 알림 전송
if (leveledUp) {
  sendToUser(user._id, 'level_up', { newLevel, tier });
}

이 코드는 운동 기록이 단순 저장에 그치지 않고 게임 보상으로 즉시 이어지는 핵심 로직이다. 운동 → 점수 → EXP → 레벨업 → 알림의 파이프라인이 단일 API 요청 안에서 모두 처리되도록 설계하였다. 레벨업 발생 시 sendToUser() 함수로 해당 사용자에게만 이벤트를 전송하여 실시간 피드백을 제공하였다.

5.3 레벨 계산 알고리즘 (server/config/gameConfig.js)

항목 내용
사용 파일 server/config/gameConfig.js
구현 목적 누적 EXP로 현재 레벨을 계산하는 수학적 공식 구현
동작 원리 삼각수(triangular number) 공식으로 레벨별 누적 EXP를 산출, while 루프로 레벨 역산 
// 레벨 N 달성에 필요한 총 EXP = 100 × N × (N+1) / 2
const getLevelRequiredExp = (level) => 100 * level * (level + 1) / 2;

// 현재 EXP로 레벨 계산
const calculateLevel = (totalExp) => {
  let level = 1;
  while (getLevelRequiredExp(level) <= totalExp) {
    level++;
  }
  return level - 1;
};

레벨이 높아질수록 요구 EXP가 증가하는 ’삼각수 공식’을 적용하여 게임의 성장 곡선을 구현하였다. 예를 들어 레벨 1은 100 EXP, 레벨 5는 1,500 EXP가 필요하여 초반에는 빠르게, 후반에는 도전적으로 성장할 수 있도록 설계하였다. 이 공식은 프론트엔드와 백엔드 모두에서 동일하게 적용되어 클라이언트-서버 간 레벨 계산 불일치를 방지하였다.

5.4 Socket.io 실시간 통신 (server/socket/socketHandler.js)

항목 내용
사용 파일 server/socket/socketHandler.js, public/js/socket.js
구현 목적 JWT 인증 기반의 개인 소켓 룸을 구성, 사용자별 실시간 알림 전달
동작 원리 연결 시 JWT 검증 → userId 기반 개인 룸(user:{id}) 입장 → 서버에서 sendToUser()로 대상 전송 
// JWT 인증 미들웨어 (Socket.io용)
io.use(async (socket, next) => {
  const token = socket.handshake.auth.token;
  const decoded = jwt.verify(token, process.env.JWT_SECRET);
  socket.userId = decoded.userId;
  next();
});

io.on('connection', (socket) => {
  // 인증된 유저는 개인 룸에 입장
  if (socket.userId) socket.join(`user:${socket.userId}`);
});

// 특정 유저에게만 이벤트 전송
const sendToUser = (userId, event, data) => {
  io.to(`user:${userId}`).emit(event, data);
};

Socket.io의 ‘룸(Room)’ 개념을 활용하여 각 사용자에게 독립된 개인 채널을 부여하였다. 이를 통해 레벨업, 업적 달성, 배틀 결과 알림이 해당 사용자에게만 전달되도록 구현하였으며, HTTP REST API와 달리 서버에서 클라이언트로 먼저 이벤트를 전송(Push)할 수 있는 구조를 실현하였다.

항목 내용

let openai = null;

5.6 운동 달력 렌더링 (public/js/workout.js — renderCalendar)

항목 내용
사용 파일 public/js/workout.js
구현 목적 외부 라이브러리 없이 순수 JavaScript로 월별 달력을 동적 생성
동작 원리 Date 객체로 해당 월의 첫 요일과 마지막 날짜를 계산, 7열 CSS Grid로 달력을 HTML 문자열로 조립 
function renderCalendar(date) {
  const year = date.getFullYear();
  const month = date.getMonth();
  const firstDay = new Date(year, month, 1).getDay();     // 첫 날 요일
  const lastDate = new Date(year, month + 1, 0).getDate(); // 마지막 날짜

  // 빈 셀(이전 달 공백) + 날짜 셀 생성
  for (let i = 0; i < firstDay; i++) html += `<div></div>`;
  for (let d = 1; d <= lastDate; d++) {
    const isToday = (dateStr === todayStr);
    html += `<div class="cal-day ${isToday ? 'today' : ''}">${d}</div>`;
  }
  grid.innerHTML = html;
}

외부 캘린더 라이브러리 없이 Date 내장 객체만으로 월별 달력을 완전히 구현하였다. getDay()로 첫 날의 요일을 파악하여 공백 셀을 삽입하고, new Date(year, month+1, 0).getDate()로 해당 월의 마지막 날짜를 구하는 JavaScript의 특성을 활용하였다. 달력 날짜에 운동 기록이 있으면 별도 표시를 추가하여 직관적인 기록 현황 파악이 가능하도록 구현하였다.

8. 느낀점

8.1 개발 과정에서 배운 점

이번 프로젝트를 통해 프론트엔드와 백엔드가 어떻게 REST API와 Socket.io로 연결되는지 전체 흐름을 직접 경험하였다. 특히 SPA 라우터를 직접 구현하면서 React·Vue 같은 프레임워크가 내부에서 어떤 원리로 동작하는지 깊이 이해하게 되었다. 또한 JWT 인증, 소켓 룸, MongoDB 스키마 설계 등 실제 서비스에서 사용되는 기술 스택을 직접 구현함으로써 웹 개발 전반에 대한 이해도가 크게 향상되었다.

8.2 어려웠던 점

가장 어려웠던 부분은 Socket.io와 JWT 인증을 결합하는 작업이었다. HTTP 요청과 달리 소켓 연결은 헤더 구조가 달라 인증 토큰을 별도로 전달해야 했으며, 연결 중단 시 재연결 처리, 개인 룸 관리 등 HTTP API에서는 고려하지 않아도 되는 부분들을 추가로 설계해야 하였다. 또한 순수 JavaScript만으로 SPA를 구현하면서 페이지 이동 시 이벤트 리스너가 중복 등록되는 문제가 발생하여 eventsBound 플래그로 중복 등록을 방지하는 방법을 학습하였다.

8.3 해결 과정

Socket.io 인증 문제는 공식 문서와 AI의 도움을 통해 handshake.auth.token 방식으로 해결하였다. 이벤트 중복 등록 문제는 바인딩 여부를 추적하는 bool 플래그를 각 모듈에 추가하여 해결하였다. 전반적으로 에러 메시지를 검색하고, AI에게 구체적인 상황을 설명하며 질문하는 방식으로 대부분의 문제를 해결할 수 있었으며, 이 과정에서 스스로 문제를 분석하고 해결하는 디버깅 능력이 향상되었다고 느꼈다.
